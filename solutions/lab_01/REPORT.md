### Часть 3. AST и байткод

Команда показывает версию установленного интерпретатора Python. На момент выполнения лабораторной работы версия `3.14.7` является последней стабильной (для хоста ОС Linux).

```bash
$ python --version
Python 3.14.7
```

AST (Abstract Syntax Tree) - абстрактное синтаксическое дерево - является представлением исходного кода программы, где каждый узел соответствует синтаксической конструкции языка. Построение дерева обычно является одним из следюущих шагов после токенизации. Древовидная структура исходного кода полезна для кодогенерации, статического анализа кода и пр.

```bash
$ python -m ast task_1.py
Module(
   body=[
      # ...

      # Присваивание переменной course значения "Python"
      Assign(
         targets=[
            Name(id='course', ctx=Store())],
         value=Constant(value='Python')),

      # Присваивание переменной hourse результата выполнения выражения 4 * 2
      Assign(
         targets=[
            Name(id='hours', ctx=Store())],
         value=BinOp(
            left=Constant(value=4),
            op=Mult(),
            right=Constant(value=2))),

      # Вызов print()
      Expr(
         value=Call(
            func=Name(id='print', ctx=Load()),
            args=[
               JoinedStr(
                  values=[
                     FormattedValue(
                        value=Name(id='course', ctx=Load()),
                        conversion=-1),
                     Constant(value=': '),
                     FormattedValue(
                        value=Name(id='hours', ctx=Load()),
                        conversion=-1),
                     Constant(value=' часов')])]))])
```

Байткод - это высокоуровневое промежуточное представление кода. Он предназначен для выполнения не процессором, а интерпретатором. В отличие от машинного кода, он является по большей частью кроссплатформенным, но может зависить от версии интерпретатора. Байткод работает не с регистрами и сырой памятью, а с виртуальным стеком, кучей и динамической типизацией, что делает его гораздо более абстрактным, чем машинный код.

```bash
$ python -m dis task_1.py
  # ...
              # Загрузка константы "Python"
  7           LOAD_CONST               1 ('Python')
              STORE_NAME               1 (course)


              # Загрузка оптимизированной (вычисленной) константы 4 * 2
  8           LOAD_SMALL_INT           8
              STORE_NAME               2 (hours)

              # Загрузка функции print()
  9           LOAD_NAME                0 (print)
              # Добавление функции на стек
              PUSH_NULL
              # Загрузка переменной для f-строки
              LOAD_NAME                1 (course)
              FORMAT_SIMPLE
              # Загрузка константы f-строки
              LOAD_CONST               2 (': ')
              # Загрузка переменной для f-строки
              LOAD_NAME                2 (hours)
              FORMAT_SIMPLE
              # Загрузка константы f-строки
              LOAD_CONST               3 (' часов')
              BUILD_STRING             4
              CALL                     1
              # Выход из области выполнения функции
              POP_TOP
              # Результат функции print()
              LOAD_CONST               4 (None)
              RETURN_VALUE
```

### Обяснение

8. Попытка изменить символ строки `student`:

   ```python
   student = "Анна Смирнова"
   # ...
   student[0] = "О"
   ```

   приводит к следующей ошибке интерпретатора:

   ```text
   TypeError: 'str' object does not support item assignment
   ```

   Данная ошибка возникает по причине того, что строковые объекты типа `str` являются неизменяемыми в Python. Внутренняя реализация CPython выделяет непрерывный буфер памяти под массив символов при инициализации строки и запрещает его модификацию без копирования (in-place): любая операция, изменяющая текст, требует создания нового объекта строки в памяти.

### Контрольные вопросы

1. Почему `len(symbol)` и `len(symbol.encode("utf-8"))` могут различаться?

   Функция `len()` для объекта `str` возвращает количество абстрактных символов Unicode (кодпоинтов). В случае символа "Я" кодовая позиция одна (1071 или U+042F), поэтому `len("Я") == 1`.

   Метод `.encode("utf-8")` переводит строку в последовательность байтов. UTF-8 является кодировкой переменной длины: ASCII-символы кодируются одним байтом, а кириллические символы (включая "Я") требуют два байта: `b'\xd0\xaf'`. Чем реже используется символ, тем длиннее его кодовое слово. Например, емодзи (😀) кодируются 4 байтами. Соответственно, количество байт (длина байтового массива) в строке, состоящей из одного символа "Я", закодированной в UTF-8, равно 2.

2. Что означают границы и шаг в записи `text[start:stop:step]`?

   `start` - индекс первого элемента среза (включается в результат). Если опущен, по умолчанию равен `0` при положительном шаге или концу строки при отрицательном.

   `stop` - индекс границы среза (не включается в результат). Если опущен, срез продолжается до границы строки.

   `step` - шаг смещения между индексами (по умолчанию `1`). Отрицательный шаг задаёт обратный порядок обхода.

3. Почему строка считается неизменяемым объектом, хотя методы вроде `.upper()` возвращают измененный текст?

   В самом деле, метод `.upper()` не измененяет изначальный буффер в памяти, а создаёт новый объект с изменённой копией буфера оригинальной строки. Исходная строка остаётся полностью неизменной в памяти: записав строка в переменную до вызова подобного метода, можно заметить, что после вызова метода по этому адресу остаётся оригинальная строка.

   ```python
   before = "abc"
   after = before.upper()
   print(before) # abc
   print(after) # ABC
   ```

   Инструкция присваивания связывает результат вычисления (выражения) с именем `modulus_square`.

   Имя `complex_coefficient` ссылается на объект типа `complex`.

   Чтение свойств / вызов геттеров `complex_coefficient.real`, `complex_coefficient.imag` объекта `complex_coefficient` типа `complex` позволяют получить вещественную и мнимую составные части комплексного числа, являющиеся вещественными числами `float`.

   Литерал `2` повторяется дважды, в обоих случаях служит показателем степени.

   Оператор `**` обладает наивысшим приоритетом в строке, и выполняет возведение числа в данную степень (2). Оператор `+` обладает самым низким приоритетом в данном выражении, и выполняет операцию сложения двух чисел. Оператор `=` обладает самым низким приритетом в данной строке, и выполняет операцию присваивания имени объекту (инструкция присваивания).

   Сначала выполняется `complex_coefficient.real ** 2`, затем `complex_coefficient.imag ** 2`. После этого операция сложения: `complex_coefficient.real ** 2 + complex_coefficient.imag ** 2`. Последняя операция - присваивание: `modulus_square = complex_coefficient.real ** 2 + complex_coefficient.imag ** 2`.

3. Путь программы.
   1) Интерпретатор читает исходный файл в кодировке UTF-8.
   2) Прозиводится токенизация исходного кода - разбор исходного текста на последовательную цепочку лексем (токенов): ключевые слова, операторы, идентификаторы, литералы, отступы и т.д.
   3) Парсер проверяет корректность последовательности токенов и строит AST (абстрактное синтаксическое дерево).
   4) Компилятор транслирует программу в набор инструкций для виртуальной машины - байткод.
   5) Виртуальная машина последовательно считывает и выполняет инструкции байкода.

4. Функция `input()` всегда возвращает данные в виде строкового объекта (`str`), поэтому для выполнения специфичных операций (например, арифмитические вычисления с объектами `int` или `float`) необходимо выполнить явное преобразование в желаемый тип данных.

### Контрольный вопрос

После повторного присваивания нового значения уже существующему имени старого объекта уменьшится счётчик ссылок (при отсутствии ссылок объект помечается как доступный для сборщика мусора - GC), а новый объект будет создан (либо подгружен в память из кэша), и ссылка на него будет сохранена в переменную. Таким образом, повторное присваивание изменяет привязку имени, и оно начинает указывать на новый объект, а предыдущий объект не изменяется.

## Вывод

В ходе выполнения лабораторной работы были исследованы модель выполнения программ на Python, механизмы CPython и объектная система языка.

Наиболее примечательными оказались три особенности.

1. Адреса объектов и связывание имён. Переменные в Python представляют собой именованные указатели на объекты в куче. В отличие от других высокоуровневых языков программирования (например, Java или Dart), Python не абстрагирует внутренний адрес объекта в памяти: в то время как другие языки позволяют получить хэшированное уникальное значение для каждого объекта (хэш-код), Python позволяет напрямую получить адрес объекта при помощи функции `id()`. При этом сравнение по ссылке работает так же, как в других языках: результат операции `is` является истиной только для одного и того же объекта в памяти. Оператор сравнения `==` позволяет сравнивать объекты с разными адресами, и обычно выводит `True` для эквивалентных объектов.

2. В Python 3 целые числа типа `int` обладают неограниченной разрядностью. CPython динамически масштабирует представление в виде массива цифр, позволяя без переполнения вычислять большие значения.

3. Строковые объекты типа `str` оперируют не байтовыми значенимя, а логическими единицами (кодовыми словами или кодпоинтами). Преобразование строки в кодировку переменной длины, например UTF-8, создаёт байтовый массив, длина которого может отличаться от длины соотвествующей строки.
