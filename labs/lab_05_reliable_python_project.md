# Лабораторная работа № 5. Итоговое консольное приложение «CourseTracker»

## 1. Общая информация

**Охватываемые разделы:** все разделы курса.  
**Итоговый результат:** работающее многофайловое консольное приложение с автоматическими тестами и документацией.

## 2. Постановка задачи

Необходимо разработать большое консольное приложение **CourseTracker** для управления учебным курсом и сдачей лабораторных работ.

Приложение должно позволять:

- регистрировать студентов;
- создавать лабораторные работы;
- сохранять несколько попыток сдачи;
- рассчитывать индивидуальную и групповую статистику;
- искать студентов и работы по различным критериям;
- импортировать и экспортировать данные;
- сохранять состояние между запусками;
- отменять изменения при ошибке;
- анализировать потребление памяти;
- вести журнал работы;
- работать через интерактивный консольный интерфейс.

Все требования реализуются в рамках **одного приложения**. Не следует создавать отдельные несвязанные программы для демонстрации каждой темы.

## 3. Цель работы

Объединить основные механизмы Python в законченном программном продукте: от типов данных, ссылочной модели и алгоритмов до итераторов, объектной модели, исключений, файлов, тестирования и организации проекта.

- анализировать корректность, сложность и потребление памяти программы.

## 5. Предметная область

### 5.1. Студент

Студент содержит:

- уникальный идентификатор;
- полное имя;
- учебную группу;
- дату регистрации;
- признак активности.

Инварианты:

- идентификатор не пустой и не содержит пробелов;
- полное имя не пустое;
- в системе нельзя зарегистрировать двух студентов с одинаковым идентификатором.

### 5.2. Лабораторная работа

Лабораторная работа содержит:

- уникальный идентификатор;
- название;
- краткое описание;
- максимальный результат;
- дату окончания приема;
- множество тегов.

Инварианты:

- идентификатор и название не пустые;
- максимальный результат положительный;
- теги не содержат пустых значений и повторов.

### 5.3. Попытка сдачи

Попытка содержит:

- идентификатор студента;
- идентификатор лабораторной работы;
- номер попытки;
- полученный результат;
- дату и время сдачи;
- текстовый комментарий;
- статус: submitted, accepted или rejected.

Инварианты:

- студент и лабораторная работа существуют;
- номер попытки положительный;
- результат находится в допустимом диапазоне;
- номер следующей попытки определяется приложением.

### 5.4. Учебный курс

Курс объединяет студентов, лабораторные работы и попытки сдачи. Объект курса предоставляет операции регистрации, поиска, сдачи, построения статистики и формирования отчетов.

## 6. Основное задание

Разработайте приложение CourseTracker, запускаемое командой: python -m course_tracker

После запуска приложение загружает сохраненное состояние и открывает интерактивную командную строку:

~~~text
CourseTracker 1.0
Введите help для просмотра команд.

course-tracker>
~~~

Приложение работает до ввода команды exit. Неизвестная команда не должна приводить к аварийному завершению.

## 7. Консольные команды

### 7.1. Справка и завершение

~~~text
help
exit
~~~

Команда help выводит список команд и примеры. Команда exit сохраняет состояние и корректно завершает работу.

### 7.2. Управление студентами

~~~text
student add s001 "Анна Смирнова" P3120
student list
student show s001
student deactivate s001
student activate s001
student search смир
~~~

Требования:

- поиск не зависит от регистра;
- список сортируется по имени, группе или идентификатору;
- повторная регистрация идентификатора отклоняется;
- деактивированный студент сохраняется в истории.

### 7.3. Управление лабораторными работами

~~~text
lab add lab_01 "Базовые типы" 100 2026-10-15 python,types
lab list
lab show lab_01
lab search python
~~~

Поиск выполняется по названию, описанию и тегам. Теги хранятся как множество уникальных нормализованных строк.

### 7.4. Регистрация попыток

~~~text
submit s001 lab_01 87.5 "Первая попытка"
submission accept s001 lab_01 1
submission reject s001 lab_01 1 "Не пройдены проверки"
history s001
~~~

Приложение автоматически назначает номер попытки и время создания записи.

### 7.5. Отчеты

~~~text
report student s001
report group
report lab lab_01
report missing
top 5
~~~

Отчеты показывают:

- число попыток;
- лучший и средний результат;
- прогресс по лабораторным работам;
- список несданных работ;
- распределение результатов по диапазонам;
- рейтинг студентов;
- нескольких лидеров при одинаковом результате.

### 7.6. Импорт и экспорт

~~~text
import students data/students.csv
import submissions data/submissions.csv
export json exports/report.json
export csv exports/report.csv
save
~~~

Одна некорректная строка импорта не должна останавливать обработку остальных строк. После импорта выводится число принятых и отклоненных записей с причинами.

### 7.7. История и отмена

~~~text
snapshot create
snapshot restore
undo
~~~

Перед изменяющей командой приложение сохраняет снимок состояния. Команда undo отменяет последнее успешное изменение. Снимок должен быть независим от текущего состояния.

### 7.8. Анализ памяти

~~~text
memory
memory profile
~~~

Команда выводит:

- число основных объектов;
- размер внешних коллекций через sys.getsizeof();
- текущую и пиковую память через tracemalloc;
- сравнение памяти при получении отчета списком и генератором.

### 9. Тестирование

Используйте pytest и подготовьте небольшой набор простых модульных тестов. Проверяйте отдельные классы и функции напрямую, без запуска консольного интерфейса и без работы с настоящими файлами.

Обязательные проверки:

1. Создание корректного объекта студента.
2. Отклонение студента с пустым идентификатором или именем.
3. Отклонение повторной регистрации идентификатора.
4. Создание лабораторной работы с корректными параметрами.
5. Отклонение результата за пределами допустимого диапазона.
6. Добавление нескольких попыток и определение лучшего результата.
7. Расчет среднего результата студента.
8. Получение списка несданных лабораторных работ.

Дополнительно можно проверить рейтинг или специальные методы объекта курса.

Используйте только основные возможности pytest:

- обычный assert для сравнения результата;
- pytest.raises() для ожидаемых исключений;
- pytest.approx() для сравнения вещественных чисел при необходимости.

Достаточно разместить тесты в двух файлах:

~~~text
tests/
├── test_models.py
└── test_services.py
~~~

Пример уровня сложности тестов:

~~~python
import pytest

from course_tracker.exceptions import ValidationError
from course_tracker.models import Student, Submission


def test_student_is_created():
    student = Student("s001", "Анна Смирнова", "P3120")

    assert student.student_id == "s001"
    assert student.full_name == "Анна Смирнова"


def test_submission_rejects_too_large_score():
    with pytest.raises(ValidationError):
        Submission(
            student_id="s001",
            laboratory_id="lab_01",
            attempt=1,
            score=101,
        )
~~~

Названия параметров можно адаптировать к выбранной реализации, сохранив смысл проверок.


## 10. Интерактивный цикл

Основной цикл приложения должен:

1. Показать приглашение.
2. Получить строку пользователя.
3. Разобрать команду и аргументы.
4. Выбрать обработчик с помощью таблицы команд или match/case.
5. Выполнить прикладную операцию.
6. Показать результат или понятную ошибку.
7. Вернуться к ожиданию следующей команды.

Разбор кавычек выполняйте через shlex.split(), чтобы имена и названия могли содержать пробелы.

Не помещайте всю логику в один цикл. CLI отвечает только за ввод, вывод и вызов сервисного слоя.
